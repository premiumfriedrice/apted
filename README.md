# apted

Tailor a resume to a job description and refine it iteratively via chat.

- **Stack:** Next.js (App Router) + TypeScript + Tailwind
- **DB:** Supabase Postgres via `pg`
- **LLM:** Anthropic SDK, model `claude-sonnet-4-6`
- **Render:** Resume JSON -> `.tex` (Jake Gutierrez template macros) -> PDF via Tectonic in a separate container service

## How it works

1. Your **master resume** lives as one JSON record in Postgres. It is the only source of truth.
2. `POST /api/tailor` takes a JD, loads the master + every prior `resume_versions`, and asks Claude for a first-pass tailored draft. The draft is saved to `drafts`.
3. The builder UI shows a chat panel and a **live PDF preview**. Each chat turn calls `POST /api/edit` with the draft id + your instruction. The route loads `master + current draft`, sends `system rules + master + current draft + instruction`, and replaces the draft with the patched JSON. Chat history is **not** replayed — the draft IS the accumulated state.
4. Every edit pushes the prior JSON onto an undo stack (capped at 20). The builder exposes Undo.
5. "Save as version" snapshots the JD + current draft into `resume_versions` with an `outcome`.
6. The PDF is generated by serializing the JSON to `.tex` using Jake Gutierrez's resume template macros (`\resumeSubheading`, `\resumeProjectHeading`, `\resumeItem`, `\section`, `...ListStart/End`), then compiled with Tectonic in a dedicated container service (`compile-service/`). The builder's preview is an `<iframe>` pointed at `/api/drafts/[id]/pdf`, with a cache-busting key on `updated_at` so each edit triggers a fresh compile.
7. "Download .tex" returns the source so you can open it in Overleaf.

A note on the renderer: the JSON -> output step is encapsulated in `src/lib/tex.ts`. To swap in a Typst renderer later, add a sibling `renderResumeTyp` and teach `/api/drafts/[id]/pdf` + the compile service to handle the alternate source.

## Env vars

| Var | Required | Notes |
| --- | --- | --- |
| `DATABASE_URL` | yes | Supabase Postgres connection string (`sslmode=require`). Use the Transaction pooler URL (port 6543) for serverless. |
| `ANTHROPIC_API_KEY` | yes | Server-side only. Never exposed to the client. |
| `COMPILE_SERVICE_URL` | yes for PDF preview | Base URL of the Tectonic compile service. In dev, `http://localhost:8080`. |

Copy `.env.example` to `.env.local` and fill in.

## Run

```bash
# 1. Install
npm install

# 2. Apply the schema (creates master_resume, resume_versions, drafts)
npm run db:migrate

# 3. Seed an empty master_resume row
npm run db:seed

# 4. Start the compile service (separate terminal)
cd compile-service
docker build -t apted-compile .
docker run --rm -p 8080:8080 apted-compile

# 5. Start the app
cd ..
npm run dev
```

Then visit:

- `/` — landing
- `/master` — edit your master resume (JSON)
- `/builder` — paste a JD, get a first-pass tailor, refine via chat
- `/library` — saved versions, filterable by outcome

## API

| Method | Path | Body |
| --- | --- | --- |
| POST | `/api/tailor` | `{ jobDescription }` -> draft |
| POST | `/api/edit` | `{ draftId, instruction }` -> updated draft |
| GET | `/api/drafts/[id]` | -> draft |
| PATCH | `/api/drafts/[id]` | `{ op: "undo" }` or `{ op: "replace", content }` |
| GET | `/api/drafts/[id]/tex` | -> `.tex` source |
| GET | `/api/drafts/[id]/pdf` | -> compiled PDF |
| GET / PUT | `/api/master` | get / replace master JSON |
| GET / POST | `/api/versions` | list (filter `?outcome=`) / create |
| GET / PATCH / DELETE | `/api/versions/[id]` | inspect / update / delete |
| POST | `/api/save-fact` | `{ sectionId, itemId, bulletText }` — append a bullet to the master |

## System prompt constraints

Encoded in `src/lib/prompts.ts`:

- The master resume is the only ground truth. No invented facts.
- Past versions inform framing / emphasis only.
- If the user explicitly provides a real fact missing from the master, it may be added — and the UI should offer to save it back.
- Must fit one page. No em-dashes. No inline bold in bullets. Prefer shipped real-user work over coursework.
