## What to Build

## Better Auth Overview

Better Auth is a framework-agnostic auth library that runs in Next.js and stores sessions in your existing Postgres. Key features:
- Email/password + OAuth (Google, GitHub) out of the box
- Session management via cookies (web app) and bearer tokens (extension/API)
- Stores user/session/account tables in your Postgres
- No external vendor — it's a library, not a SaaS

### Task 7: Chrome extension authentication

The extension needs to authenticate with the web app. Two approaches:

**Recommended: Session token in extension settings**
1. User logs in to the web app
2. User goes to settings page, sees an "Extension Access" section with a session token
3. User copies the token and pastes it into the extension options page
4. Extension sends the token as `Authorization: Bearer <token>` on every API call (already supported via `authToken` in extension settings)
5. The web app's middleware validates the Better Auth session token

**Alternative: Extension login flow**
1. Extension opens a popup/tab with the web app's login page
2. After login, the extension captures the session cookie/token
3. Extension stores and sends the token

The recommended approach is simpler and reuses the existing `authToken` field in extension settings. The web app just needs an endpoint to generate a long-lived session token for the extension.

Create `POST /api/auth/extension-token`:
- Requires an authenticated session (cookie)
- Generates a long-lived bearer token tied to the user
- Returns the token for the user to copy into the extension
