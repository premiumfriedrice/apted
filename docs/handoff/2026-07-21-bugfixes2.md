## Bug 1: Wrong job description saved with application

**Symptom:** The Roblox application has the Ditto job description. The application was auto-saved with the JD from a previously tailored draft, not the JD from the current page.

**Root cause:** `autoSaveApplication()` in `extension/src/drawer.ts` line ~2166 uses `draft.jobDescription` as the JD. But `draft.jobDescription` is the JD that was used to create the draft at tailor time. If the user tailored for Ditto, then navigated to Roblox and submitted there, the draft still has Ditto's JD.

**Fix:** Use the current page's JD text from the drawer fields (`els.jdText.value`) instead of `draft.jobDescription`. The JD text area on the drawer reflects the most recent scrape, which is the correct one for the current application.

In `autoSaveApplication()`, change:
```typescript
jobDescription: draft.jobDescription || els.jdText.value,
```
to:
```typescript
jobDescription: els.jdText.value || draft.jobDescription || "",
```

This prioritizes the current JD text field (which the user sees and has presumably scraped for the current job page) over the draft's original JD.

## Bug 2: Auto-save creates 10 copies of the same application

**Symptom:** Submitting one job application creates up to 10 duplicate application records.

**Root cause:** Three issues:

1. **Double-fire from form submit + button click:** When the user clicks a submit button, BOTH the `document.addEventListener("submit", ...)` and `document.addEventListener("click", ...)` fire. The click listener checks for `type="submit"` or label matching "submit"/"apply", and the form submit listener fires too. Two calls to `autoSaveApplication()` for one action.

2. **Multiple matching buttons:** The click listener matches ANY button with "submit" or "apply" in its text. On multi-step application forms (Ashby, Greenhouse, Workday), there are buttons like "Apply" or "Submit" at earlier steps that match, triggering auto-save before the actual final submission.

3. **Race condition in dedup:** `saveInProgress` is set to true, but `isDraftSaved()` checks `chrome.storage.session` which is async. Between the `isDraftSaved` check and the `markDraftSaved` call, multiple events can fire and all pass the `isDraftSaved` check before any of them marks it saved. The `saveInProgress` guard should catch this, but if the save throws or completes fast, the flag resets before all queued events are processed.

**Fix:**

1. **Deduplicate submit + click:** In the click handler, check if the target is inside a `<form>` and if the form submit event will also fire. If the button triggers a form submit, let the submit handler do the auto-save and skip the click handler. Add a `pendingSubmit` flag:
   ```typescript
   let pendingSubmit = false;
   
   // In submit handler:
   document.addEventListener("submit", (e) => {
     if (host.contains(e.target as Node)) return;
     pendingSubmit = true;
     void autoSaveApplication();
   }, { capture: true });
   
   // In click handler, skip if a form submit is pending:
   document.addEventListener("click", (e) => {
     ...
     if (pendingSubmit) return; // form submit handler will take care of it
     if (typeAttr === "submit" || isSubmitButtonLabel(label)) {
       void autoSaveApplication();
     }
   }, { capture: true });
   
   // Reset pendingSubmit after a tick:
   // Use setTimeout(() => { pendingSubmit = false; }, 100) in the submit handler
   ```

2. **Only match final-step buttons:** Make the button label heuristic stricter. Require the button text to contain "submit application", "submit application", "apply now", "send application" — not just "apply" or "submit" alone. This prevents matching mid-flow buttons like "Continue" or generic "Apply" buttons that appear on job listings pages.

   Update `extension/src/submit-detection.ts`:
   ```typescript
   const SUBMIT_PATTERNS = [
     /submit\s+(your\s+)?application/i,
     /submit/i, // keep but lower priority
     /apply\s+now/i,
     /send\s+application/i,
   ];
   ```

3. **Stronger dedup with immediate flag:** Set a sync flag BEFORE the async `isDraftSaved` check so subsequent calls are blocked immediately:
   ```typescript
   if (saveInProgress) return;
   saveInProgress = true;  // set BEFORE async check
   if (await isDraftSaved(draft.id)) { saveInProgress = false; return; }
   ```
   Move `saveInProgress = true` above the `isDraftSaved` check.
